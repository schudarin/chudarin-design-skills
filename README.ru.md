# chudarin-figma-skills

Агенты уже умеют писать в Figma. Сами по себе они дизайнят плохо и ломают файл тихо: переменная не
привязалась, набор компонентов удалился сам, когда из него вынесли последний вариант, экран собран
из захардкоженных значений и выглядит правильно ровно до переключения темы.

Это то, что помогло на живых продуктовых файлах. Пять скилов: процесс на каждый этап работы плюс пак
записанных отказов Plugin API с обходом каждого. Каждое правило это случай, который сломался ровно так,
а не пересказ документации.

[English version](README.md)

## Для кого

Для дизайнеров. Ставится один раз, дальше вы работаете в чате: кидаете ссылку на Figma и говорите
одной фразой, что нужно. Ни кода, ни редактора кода, ни своего плагина.

Как это выглядит: вы вставляете ссылку на фрейм и пишете «задизайни экран настроек для этого
приложения». В незнакомом проекте агент сначала сам ищет то, что ему нужно знать: документ про
дизайн-систему, готовые экраны, переменные в самом файле. Спрашивает только то, чего не нашёл, не
больше двух вопросов. Записывает и больше не спрашивает. Дальше работает от ваших компонентов и
переменных, перечитывает каждую привязку, которую поставил, вместо того чтобы считать её
применённой, и показывает результат. Просите поменять один элемент, и меняется он, а не экран вокруг.

## Пять скилов

| Скил | Вы пишете примерно так | Что происходит |
|---|---|---|
| `figma-plan-user-flows` | «Какие экраны нужны для оформления заказа?» | Получаете все экраны и состояния, точки входа и выхода, структуру страниц файла, до того, как что-то нарисовано |
| `figma-audit-design-system` | «Пройди по файлу и скажи, что есть в дизайн-системе» | Агент читает файл и отчитывается: компоненты, токены, паттерны, долг; по просьбе пишет страницы документации. В остальном только чтение |
| `figma-design-screens` | «Задизайни экран настроек» · «Поменяй шапку на этом фрейме» | Сам процесс дизайна: откуда берётся стиль, бриф на каждый экран, проверки после, правки в согласованной работе по одному элементу |
| `figma-plugin-api-rules` | ничего, грузится сам | Реальные отказы Plugin API и обход каждого. Загружается до того, как агент что-то запишет в ваш файл |
| `figma-fix-variable-bindings` | «Переменные на этой странице отвалились, почини» | Находит отвязанные, осиротевшие и захардкоженные значения, показывает отчёт, привязывает обратно только после вашего подтверждения |

Пять файлов `SKILL.md` и тематические файлы за ними. Часть из них пак по Plugin API: компоненты и
варианты, инстансы, лейаут и геометрия, текст и шрифты, переменные и режимы, коннекторы, аннотации,
гигиена публикации, FigJam, ссылки прототипа, слой инструментов, сборка экрана из кода. Остальные это
чек-листы аудита, брифы на экран, проверки после сборки и правила UX, маршрутизируемые по тому, что есть
на экране. Всё это обычный Markdown. На вашей машине ничего не запускается и никуда не отправляется.

## Почему это не просто промпт

Почти всё, что ломается между агентом и Figma, ломается молча. Вызов вернул успех, файл выглядит
правдоподобно, привязка не применилась. `setBoundVariable('cornerRadius', v)` привязывает четыре
поля по углам, а сводный ключ, который вы проверили, остаётся пустым. Лицензионный шрифт,
отсутствующий в песочнице, роняет запись текста так, что это читается как ваша ошибка. У инстанса в
`children` нет скрытых потомков, и инвентаризация, собранная по нему, врёт.

Вежливой формулировкой это не лечится. Лечится знанием случая и проверкой результата. Этим файлы и
набиты.

## Установка

Пять шагов: место в Figma, Claude Code, три плагина, один перезапуск в конце.

**Или отдайте это агенту.** Если Claude Code уже стоит, вставьте в чат:

```
Поставь https://github.com/schudarin/chudarin-figma-skills: выполни команды из шагов 3, 4 и 5 раздела «Установка» в README
```

Команды агент выполнит сам. Три вещи остаются на вас: место из шага 1, перезапуск и вход в Figma
из шага 6.

### 1. Место в Figma, которое пускает агента

Figma ограничивает агента не скилом, а типом места (seat):

| Место | Starter | Professional | Organization, Enterprise |
|---|---|---|---|
| View, Collab | 20 чтений в месяц | 6 чтений в месяц | 6 чтений в месяц |
| Dev, Full | 200 в день, 10 в минуту | 200 в день, 15 в минуту | 600 в день, 20 в минуту |

Места View и Collab хватит один раз посмотреть, а не работать. Нужно Dev или Full.

Лимиты считают чтения. Запись в файл не считается и бесплатна, пока идёт бета Figma. Источник и
актуальные цифры: [Rate limits & access](https://developers.figma.com/docs/figma-mcp-server/rate-limits-access/)
в документации Figma для разработчиков, на сентябрь 2026.

### 2. Claude Code

Claude Code это агент от Anthropic. Живёт в Терминале, это чёрное окно, а не редактор кода.

Откройте Терминал (⌘ + Пробел, наберите `Terminal`, Enter), вставьте строку и нажмите Enter:

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

Когда закончится, наберите `claude` и Enter, запустится чат. Выход через `/exit`.
Полная инструкция: [docs.claude.com/en/docs/claude-code/setup](https://docs.claude.com/en/docs/claude-code/setup).

### 3. Связь с Figma

У Figma есть свой плагин для Claude Code. В нём и соединение (MCP-сервер), и собственные инструкции
Figma для агента. Эти скилы надстраиваются над ними:

```bash
claude plugin install figma@claude-plugins-official
```

### 4. Сами скилы

```bash
claude plugin marketplace add schudarin/chudarin-figma-skills
claude plugin install chudarin@chudarin
```

Обе команды работают и внутри чата: `/plugin marketplace add …` и `/plugin install …`.

### 5. superpowers

Эти скилы решают, *как* работать в Figma, когда задача уже ясна. Они не решают, *какая* задача.
Это делает `superpowers` от Anthropic: на фразу «добавь кнопку» первым срабатывает
`brainstorming`, спрашивает, какой проект и какой файл, и только потом передаёт дальше. Без него
агент начнёт не с той страницы.

```bash
claude plugin install superpowers@claude-plugins-official
```

### 6. Перезапуск и вход в Figma

Закройте Claude Code и запустите заново. Плагины подхватываются при старте, так что одного
перезапуска хватит на все три. Потом наберите в чате `/mcp`, выберите `figma` и пройдите вход:
Figma откроется в браузере и один раз попросит разрешить доступ.

Проверьте, что скилы встали:

```bash
claude plugin details chudarin@chudarin
```

В списке пять скилов. Внутри чата они называются `chudarin:figma-design-screens`,
`chudarin:figma-plugin-api-rules` и так далее. Агент подхватывает их сам, когда задача совпадает,
но можно назвать нужный напрямую.

## Откуда запускать

Заведите по папке на продукт и всегда запускайте Claude Code из неё:

```bash
mkdir -p ~/Design/my-product
cd ~/Design/my-product
claude
```

Папка важна. `figma-design-screens` записывает всё, что узнал о проекте (дизайн-систему, источник
стиля, файл Figma), в `.claude/design.md` внутри неё, и каждая следующая сессия читает этот файл, а
не спрашивает вас заново. Запустите из другой папки, и начнёте с нуля.

## Первая задача

1. В Figma правый клик по фрейму или странице → **Copy link to selection**.
2. В Терминале: `cd ~/Design/my-product`, затем `claude`.
3. Вставьте ссылку и добавьте одну фразу.

```
https://figma.com/design/…  — разбери эту страницу и скажи, что есть в дизайн-системе
```

```
https://figma.com/design/…  — спланируй экраны для восстановления пароля
```

```
https://figma.com/design/…  — отступы у этих карточек захардкожены, верни их на переменные
```

Ссылку кидайте всегда. Без неё агент угадывает, какой файл и какая страница имеются в виду, и
угадывает мимо.

## Какой скил когда

- «Какие экраны нужны под эту фичу?» → `figma-plan-user-flows`
- «Что есть в дизайн-системе, где долг, задокументируй» → `figma-audit-design-system`
- «Задизайни / поменяй / пересобери этот экран» → `figma-design-screens`, он сам подтягивает
  `figma-plugin-api-rules`
- Любая запись в Figma → `figma-plugin-api-rules`
- «Переменные отвалились / захардкожены / Figma пишет „Variable was deleted“» →
  `figma-fix-variable-bindings`

## Обновить и удалить

```bash
claude plugin update chudarin@chudarin      # свежая версия, применяется после перезапуска
claude plugin uninstall chudarin@chudarin   # удалить
claude plugin list                          # что стоит сейчас
```

## Если не работает

| Что видите | Что это значит | Что сделать |
|---|---|---|
| Агент пишет, что не может достучаться до Figma | Соединение не авторизовано | Наберите `/mcp`, выберите `figma`, войдите через браузер |
| Останавливается после нескольких чтений | Лимит места: 6 чтений в месяц на View или Collab, 20 на Starter | Попросите место Dev или Full на платном плане |
| Чтения начали отваливаться ближе к вечеру | Дневной лимит чтений: 200 на Professional, 600 на Organization и Enterprise, на все инструменты | Продолжите завтра или разбейте работу на дни |
| Агент работает не в том файле или не на той странице | Ссылки не было, он угадал | Кидайте ссылку каждый раз. И поставьте `superpowers` из шага 5 |
| Скилы не появились | Плагин стоит, но сессия старая | Закройте Claude Code и запустите заново |
| Агент поменял то, что не просили | Figma хранит историю файла | **File → Show version history**, восстановите прошлую версию |

## Что поставить рядом

**Ничего из этого раздела не обязательно.** С плагинами из шагов 3 и 5 пять скилов работают
сами по себе. Всё ниже делает прогоны лучше, и всё это чужие скилы, не мои.

`figma-design-screens` использует ещё один визуальный скил под тип задачи: мобильный, веб, моушен
или графики, смотря что за экран. Ни один из них не обязателен: скил читает список скилов, которые
реально есть в сессии, подтягивает подходящий по типу задачи, а если полка пуста, говорит об этом
и работает от вашей дизайн-системы, готовых экранов и своих правил копирайта и контролов. Имена,
которые он ищет: `mobile-app-ui-design`, `frontend-design`, `impeccable`,
`design-motion-principles`, `emil-design-eng`, `dataviz` и `design-critique` для проверки.

### Как их поставить

`frontend-design` от самой Anthropic, ставится как плагин:

```bash
claude plugin install frontend-design@claude-plugins-official
```

`dataviz` встроен в Claude Code. Ставить нечего.

Остальные пять лежат на GitHub и ставятся через Skills CLI с [skills.sh](https://skills.sh). Ему
нужен Node.js: наберите в Терминале `node -v`, и если в ответ `command not found`, сначала
поставьте LTS-сборку с [nodejs.org](https://nodejs.org). Дальше по одной команде на скил, в
Терминале, не в чате:

```bash
npx skills add pbakaus/impeccable@impeccable -a claude-code -g -y
npx skills add kylezantos/design-motion-principles@design-motion-principles -a claude-code -g -y
npx skills add emilkowalski/skills@emil-design-eng -a claude-code -g -y
npx skills add ceorkm/mobile-app-ui-design@mobile-app-ui-design -a claude-code -g -y
npx skills add anthropics/knowledge-work-plugins@design-critique -a claude-code -g -y
```

Флаги: `-a claude-code` выбирает агента, `-g` ставит для всех проектов, а не только для текущей
папки, `-y` пропускает подтверждение. Уберите `-g`, чтобы поставить в один проект. Для Codex
замените `-a claude-code` на `-a codex`.

Закройте Claude Code, откройте заново и проверьте, что встало:

```bash
npx skills list
```

Потом `npx skills check` покажет, у каких из них вышла новая версия, а `npx skills update`
обновит все разом.

Любой другой скил со skills.sh ставится так же: `npx skills add owner/repo@skill-name`, а
`npx skills find <слово>` ищет по каталогу прямо из Терминала. Читайте лицензию, прежде чем ставить
чужую работу. Если какое-то имя отсюда уже переехало или исчезло, ничего не сломается:
`figma-design-screens` проверяет полку в рантайме, а не доверяет этому списку, так что мёртвое имя
ничего не стоит.

Ещё пригодится свой скил под тексты: подписи кнопок и текст интерфейса. Эти скилы ставят текст на
место, но не пишут его.

## Другие агенты и установка руками

<details>
<summary>Codex или Claude Code без системы плагинов</summary>

Каждый скил это папка: `SKILL.md` + `references/` + `agents/openai.yaml` для Codex. Skills CLI с
[skills.sh](https://skills.sh) ставит их в любой агент, который знает; ему нужен Node.js.

```bash
npx skills add schudarin/chudarin-figma-skills -a codex -g -y          # Codex
npx skills add schudarin/chudarin-figma-skills -a claude-code -g -y    # Claude Code без системы плагинов
```

`-g` ставит для всех проектов, без него для одного. `npx skills update` потом подтянет новые
версии. В Codex скил вызывается явно через `$skill-name`; неявный вызов включён у всех пяти.

Без Node.js клонируйте и слинкуйте папки туда, где агент ищет скилы: `~/.agents/skills/` для
Codex, `~/.claude/skills/` для Claude Code:

```bash
git clone https://github.com/schudarin/chudarin-figma-skills ~/chudarin-figma-skills
mkdir -p ~/.agents/skills
for s in ~/chudarin-figma-skills/skills/*; do ln -sfn "$s" ~/.agents/skills/; done
```

После `git pull` прогоните цикл заново, чтобы подтянуть обновления.

На любом другом агенте это обычный Markdown. Отдайте `SKILL.md` агенту как контекстный файл перед
работой с Figma.

В любом случае нужен MCP-сервер Figma и собственные инструкции Figma `figma-use`, загруженные до
первого вызова `use_figma`: в Claude Code их даёт плагин Figma, в остальных местах MCP-ресурс
`skill://figma/figma-use/SKILL.md`.

</details>

## Как дополнять

У каждого скила описан свой протокол расширения; у `figma-plugin-api-rules` он в конце
[`SKILL.md`](skills/figma-plugin-api-rules/SKILL.md). Факты про один конкретный файл Figma (ID нод,
местные договорённости) сюда не идут. Держите их в `<project>/.claude/design.md` или в своих
заметках.
